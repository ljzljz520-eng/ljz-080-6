# 博物馆文物借展物流台

面向「策展人 — 库房 — 物流方 — 外部展馆」四方的文物借展全流程协同台。
状态机驱动借展流转，温湿度自动比对环境要求并告警；**任何一次开箱都强制登记在场人员并上传照片留痕**；外部展馆只能看到本馆借到的文物（服务端数据隔离，越权访问返回 404）。

## 角色与权限

| 角色 | 账号 | 能做什么 |
| --- | --- | --- |
| 策展人 | `curator` | 发起借展：文物编号、保险金额、环境要求（温湿度/照度/防震）、展期、借入展馆；查看全部单据 |
| 库房 | `keeper` | 确认装箱（箱号/铅封/现状/**装箱照片**）、安排发运、归还相关操作 |
| 物流方 | `logistics` | 在途回传位置与温湿度（越界自动告警）、到馆签收、撤展归还发运 |
| 外部展馆 | `museum1` / `museum2` | **仅能看到本馆借到的文物状态**；到馆后登记开箱（人员+照片） |

所有演示账号密码均为 `demo123`。

## 流程状态

```
待装箱 requested → 已装箱 packed → 在途 shipped → 已到馆 arrived → 已归还 returned
```

- 策展人录入文物编号、保险金额、温湿度/照度/防震等环境要求与起止展期；
- 库房装箱必须拍照（multer 上传，单文件 ≤10MB），记录箱号与铅封号；
- 物流每到一处可回传温湿度，系统按该文物约定区间判定，越界在列表/详情/时间线三处标红告警；
- 到馆签收记录签收人与地点；
- **任何一次开箱（到馆/展中检查/撤展复装/归还点交）都必须填写全部在场人员并上传照片，否则服务端 400 拒绝**；
- 每个动作都写入不可由前端改写的全程时间线。

## 运行

```bash
npm start        # 等价 node server.js，默认 http://localhost:3000
```

首次启动自动生成演示数据（`server/data/db.json`）与占位留痕照片（SVG）。
删除 `server/data/db.json` 即可重置。

## 技术说明

- Node.js + Express 5，会话用 `express-session`（HttpOnly Cookie），文件上传用 `multer`；
- 零数据库依赖：JSON 文件原子写入持久化（`server/db.js`），可平滑替换为 SQLite/PostgreSQL；
- 前端为原生 JS 单页应用（`public/`），无构建步骤；
- 安全要点：服务端鉴权 + 角色鉴权 + 借展单归属校验 + 状态机校验 + 输入校验；外部展馆访问他馆单据一律 404（不暴露资源存在性）。
- 演示环境密码为明文、会话密钥硬编码；生产部署请改用密码哈希、环境变量密钥与反向代理 HTTPS。

## 目录

```

server/seed.js         # 演示数据（2 个展馆 / 5 个账号 / 3 张不同状态借展单）
server/uploads/        # 留痕照片存储
server/data/db.json    # 运行时数据（自动生成）
public/                # 前端 SPA
```
