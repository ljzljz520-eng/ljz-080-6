# 博物馆文物借展物流台

面向博物馆借展业务的全流程留痕系统：策展人发起借展 → 库房确认装箱 → 物流发运并回传温湿度 → 到馆签收 → 开箱留证。**任何一次开箱都强制记录在场人员并上传照片**；外部展馆只能查看本馆借到的文物状态。

## 角色与权限（RBAC）

| 角色 | 账号 | 可执行操作 |
| --- | --- | --- |
| 策展人 | `curator` / 陈策展 | 发起借展（文物编号、保险金额、环境要求、展期）、查看全部借展单 |
| 库房 | `warehouse` / 王库房 | 确认装箱，可一并留存装箱前点交开箱记录 |
| 物流方 | `logistics` / 李运输 | 确认发运、回传温湿度、登记到馆签收 |
| 外部展馆 | `museum`（苏州河美术馆）/ `museum2`（临安城市展览馆） | **仅可见本馆借到的文物**，可对到馆文物开箱留证；保险金额等内部信息不可见 |
| 管理员 | `admin` | 拥有全部权限 |

所有演示账号密码均为 `123456`。

## 状态机

```
pending_packing 待装箱
      └─ 库房确认装箱 ─▶ packed 已装箱
              └─ 物流确认发运（登记承运方） ─▶ in_transit 运输中
                      ├─ 物流回传温湿度（可多次）
                      └─ 物流到馆签收（登记签收人） ─▶ arrived 已到馆签收
```
任何状态下（装箱之后）各业务相关方均可补登开箱记录；**开箱 = 在场人员 + 至少 1 张现场照片，二者缺一不可**，每次开箱同时进入借展单流转时间线。

## 安全要点

- 服务端会话鉴权（httpOnly Cookie）+ 角色校验，前端按钮仅做展示，越权操作在 API 层拒绝。
- 外部展馆数据隔离：借展单列表、详情、照片下载均在服务端按 `museumId` 过滤，无法通过修改 URL 越权查看（照片 URL 为随机不可猜文件名，且访问时再次鉴权）。
- 保险金额字段对外部展馆从 API 响应中剔除。
- 上传限定图片类型、单张 10MB、单次 9 张；文件名服务端随机生成。

## 运行

```bash
npm install
npm start
# 打开 http://localhost:3000
```

无原生依赖（环境缺少编译工具链也可运行）。数据存储于 `data/db.json`、上传照片在 `uploads/`；删除 `data/db.json` 后重启会重新生成 3 条演示借展单（覆盖四种状态中的三种）。

## 目录

- `server.js` — Express API：认证、RBAC、状态流转、温湿度、开箱留证、照片鉴权
- `lib/db.js` — 零依赖 JSON 文件存储 + 种子数据
- `public/` — 原生 HTML/CSS/JS 单页应用（四种角色工作台）

## 主要 API

| 方法 | 路径 | 角色 |
| --- | --- | --- |
| POST | `/api/login` `/api/logout` | 所有人 |
| GET | `/api/loans` | 登录用户（展馆自动过滤本馆） |
| POST | `/api/loans` | 策展人/管理员 |
| GET | `/api/loans/:id` | 登录用户（馆际隔离） |
| POST | `/api/loans/:id/pack` | 库房/管理员（multipart，可附开箱照片） |
| POST | `/api/loans/:id/ship` | 物流/管理员 |
| POST | `/api/loans/:id/arrive` | 物流/管理员 |
| POST | `/api/loans/:id/env-logs` | 物流/管理员 |
| POST | `/api/loans/:id/open-events` | 登录用户（人员+照片强制） |
| GET | `/api/photos/:photoId` | 登录用户（馆际隔离） |
